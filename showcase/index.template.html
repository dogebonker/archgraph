archgraph showcase

archgraph reports on well-known open-source repositories, each scanned at a pinned commit.

archgraph turns a repository's import graph into evidence for architecture decisions: per-module coupling and cohesion, module cycles with their smallest break set, and findings that propose file moves backed by a simulation of each move. It collects file-level imports with dependency-cruiser (TypeScript/JavaScript) or grimp (Python); for Python it also parses files with the standard library's ast, without running them, to tell imports inside functions apart.

Each repository was fetched at the commit shown (a shallow fetch of exactly that commit) and one folder of it was scanned with the flags shown, with the default excludes (tests, generated code, and build output at the folder's root or ignored by git). Nothing was installed into the repositories, so imports of npm packages count as unresolved, and imports between workspace packages leave the scanned folder. A module is a folder truncated to the scan depth below the source root.

No co-change analysis: the clones are shallow, so hidden-coupling never appears here. Imports are not semantics: dependency injection, event buses, string lookups, reflection and dynamic imports without static strings are invisible to the graph. Findings are moves with evidence for a person to judge, not verdicts. The repositories are well-known examples chosen for their size and layout; these reports are reading aids, not endorsements or criticism of the projects.
